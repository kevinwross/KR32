## 2. Build and gate

CMake, Ninja and ctest are not on `PATH` on Windows; use the Visual Studio
bundled copies named in `AGENTS.md`.

```powershell
$cmake = "C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"
$ctest = "C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe"
& $cmake --preset windows-msvc            # configure, once per machine
& $cmake --build --preset windows-msvc-debug
```

Gate scripts size the job count to the machine (Arm64 → 4, otherwise 80% of
`NUMBER_OF_PROCESSORS`, sanitizer capped at 4):

```powershell
pwsh -File scripts/run-gate.ps1          # Windows: build + ctest
```

```sh
bash scripts/run-gate.sh                 # WSL / Linux, same rule
```

**Two traps learned the hard way:**

1. On this machine `pwsh -File scripts/run-gate.ps1` several times exited `-1`
   with no summary at all — an interruption in the nested shell, not a test
   failure. Running `ctest --preset windows-msvc-debug -j 9` directly gave a
   clean result every time. If a gate exits `-1` with no summary, re-run it
   directly before investigating, and never report it as a failure or a pass.
2. **The WSL build tree can be stale.** `ctest --preset linux-gcc` will happily
   run yesterday's binary. Always `cmake --build --preset linux-gcc` first and
   read its result; a build that fails under `-Werror` leaves the old binary in
   place and the tests "pass" against code you did not compile. This happened
   twice, once in a way that made a commit message claim a WSL result before it
   had been established.

Sanitizer gate (not run in this session, configure it on the new machine):

```sh
cmake --preset linux-asan && cmake --build --preset linux-asan && ctest --preset linux-asan
```

## 3. Verification discipline this project rewards

- **Measure CPU work, not wall time.** `ctest` prints `sec*proc` per label.
  Wall time was contaminated twice by another build on the same machine (220 s
  and 264 s for identical work). Sum `sec*proc` from a **full log**, never a
  `tail` capture — a truncated capture overstated the WSL figure by half.
- **A wrong debug record is worse than a missing one.** Twice this week a record
  that pointed at the wrong place was shipped-looking and wrong, while an absent
  record merely fell back to the frame slot.
- **Assembly-shape tests pass on a broken compiler.** The `catch` miscompile
  survived 96 green tests; what caught it was a test that *runs* the program and
  asserts the exit code. When a bug is behavioural, test behaviour.
- **Screenshots find what tests cannot.** Five debugger bugs were found by the
  operator looking at the window, not by the suite. `grab-window` (a skill on
  this machine) captures a PNG of a live window; `read_image` opens it.

## 5. Open threads, most actionable first

### 5.1 The Variables panel has no tests (highest risk)

Three panel features shipped this week with **no test**: collapsible aggregates,
the right-click inspector, and the `+`/`-`/`->` markers. One of them (collapse)
shipped broken and the operator caught it. Gates stay green either way.

The fix is small and removes the class of problem: move the row-text and
row-building decision out of `draw_variables` in `src/ui/debugger_ui.cpp` into a
pure function that takes the entry (name, type, value, aggregate flag, expanded
flag) and returns the text and the child list. The model side already exists —
`debug::member_entries` and `debug::pointee_type` — so this is the last mile.
Then a test can assert `+ root -> 0x…`, `- node -> 0x…`, and no marker on a
scalar, without a window.

### 5.2 `libcpp` takes ~42 s at `-O1` (linear, high constant)

Measured, not guessed: a synthetic input of independent functions takes 12.2 s at
`-O1` for 200 functions and 24.8 s for 400, with the `-O1`/`-O0` ratio unchanged
at 38x/39x. **Nothing is quadratic**; the cost is ~2.5 ms per instruction. The
suspects are constant-factor: the pipeline re-parses every line in each of ~70
passes, and `debug_function_names`/`debug_slot_names` walk the whole file once per
promotion pass.

Instrumentation attempts failed twice (a macro whose body a regex rewrote into a
self-call; `std::getenv` raising MSVC C4996 under `/WX`; a `constexpr` guard built
empty so it measured nothing). The next attempt should be blunt: wrap each *half*
of `optimize_assembly` in `#if 0`, halve the search, five runs of 40 s beats
instrumenting 71 call sites.

### 5.3 C++/C code-size difference is accepted, not fixed

C++ reduces 22.8% by instruction count against C's 44.3%; by ticks they are level
(1.18x vs 1.13x). Closing it means promoting inside functions that carry a real
exception handler, and a `catch` reads the frame slot that promotion rewrites. The
shared-slice guard that keeps exceptions correct stays. Recorded in
`docs/optimizations.md` and `implementation.md`.

### 5.4 `JMP` to the next instruction at `-O0`

Visible in unoptimized disassembly. A cleanup pass was written, tested, and
**reverted**: it reintroduced the `catch` miscompile. `-O0` output is allowed to be
naive, and the window now builds optimized so it is no longer what the operator
sees. If it is attempted again, the exception regression test must be the gate.
